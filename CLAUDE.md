# campaign-report

CLI, який зводить два CSV (витрати і доходи по кампаніях) в одну таблицю: кампанія, витрати, дохід, ROI + рядок "Разом". На виході CSV або markdown.

## Загальне

Відповідай українською. TypeScript strict, Node, ESM, тести на vitest.
CSV парсимо через csv-parse, руками через split не треба.
Нові залежності не додавай, поки я не погоджу.

## Команди

npm test
npx tsc --noEmit
npm run build
node dist/cli.js --spend <file> --revenue <file> --format md|csv [--out <file>]

## Структура

src/parse.ts - читає CSV, повертає нормальні рядки і список помилок
src/aggregate.ts - зведення по кампаніях, ROI, Разом
src/format.ts - вивід в csv/md
src/cli.ts - тільки аргументи, файли і виклик функцій вище
fixtures/ - вигадані CSV під різні випадки
tests/ - юніт-тести на функції і e2e на кожну папку з fixtures

parse, aggregate і format без побічних ефектів, щоб їх можна було нормально тестувати.

## Правила підрахунку

ROI = (дохід - витрати) / витрати * 100%. Якщо витрати <= 0, в ROI ставимо "-".
Якщо кампанія є тільки в одному файлі, вона все одно має бути в звіті, а відсутнє значення = 0.
Якщо кампанія повторюється в кількох рядках, суми додаємо.
ROI в рядку Разом рахуємо від загальних сум, а не як середнє по кампаніях.
Гроші рахуємо в центах (сума * 100, ціле число), виводимо з двома знаками після коми.
У назвах кампаній обрізаємо пробіли по краях.
Розділювач може бути , або ; а дробова частина через . або ,

## Погоджені рішення (після плану)

Колонки шукаємо за назвою в заголовку: campaign + spend або revenue. Регістр і пробіли в заголовку не важливі, зайві колонки ігноруємо. Якщо потрібної колонки нема, це помилка з назвою файлу.
Назви кампаній порівнюємо без регістру (trim + toLowerCase). Показуємо написання, яке трапилось першим. Якщо злились різні написання, у звіт помилок іде попередження "злито: ...".
При розділювачі , кома як дріб тільки в лапках ("1,50").
Більше 2 знаків після коми - помилка, не округлюємо.
Мінусові суми в рядках дозволені. Якщо сумарні витрати кампанії <= 0, ROI = "-".
Звіт у stdout або --out. Помилки в stderr, а якщо задано --out, то ще й у <out>.errors.csv. Код виходу 0 якщо звіт побудовано, 1 якщо погані аргументи або файл не прочитався.
Заголовки звіту англійською: campaign,spend,revenue,ROI. Підсумковий рядок називається Total (це рядок "Разом" з умови).
Файл 0 байт = порожній, не помилка. Попередження в stderr.
Типи лежать у src/types.ts. Білд через tsconfig.build.json.
expected для fixtures/basic рахую я сам. Expected для інших папок агент показує мені до написання тестів.

## Прогрес

Усі кроки плану готові: parse, aggregate, format, cli, e2e. Два раунди незалежного рев'ю виправлені, решта в README "Відомі обмеження". Деталі в git log.

Якщо рядок битий (порожня сума, не число, немає назви кампанії), він іде в звіт помилок: файл, номер рядка, що не так. Пропускати мовчки не можна.

Дані тільки вигадані.
