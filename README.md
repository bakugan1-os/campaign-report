# campaign-report

CLI, який зводить два CSV — витрати і доходи по кампаніях — в одну таблицю `campaign, spend, revenue, ROI` з рядком `Total`. Вихід у CSV або markdown.

Битий рядок ніколи не зникає молча: він або в звіті помилок, або файл відхиляється цілком.

```
$ node dist/cli.js --spend fixtures/basic/spend.csv --revenue fixtures/basic/revenue.csv --format md

| campaign | spend | revenue | ROI |
| --- | ---: | ---: | ---: |
| black-friday | 3400.00 | 2890.75 | -14.98% |
| brand-awareness | 750.25 | 1500.00 | 99.93% |
| winter-sale | 1200.50 | 2400.00 | 99.92% |
| Total | 5350.75 | 6790.75 | 26.91% |
```

## Встановлення

Перевірено на Node 24. Для запуску тестів потрібен Node 22.12+ або 24+ — це вимога vitest.

```
npm install
npm run build
```

## Використання

```
node dist/cli.js --spend <file> --revenue <file> --format md|csv [--out <file>]
```

| Прапорець | Обовʼязковий | Що робить |
| --- | --- | --- |
| `--spend <file>` | так | CSV з витратами: колонки `campaign` і `spend` |
| `--revenue <file>` | так | CSV з доходами: колонки `campaign` і `revenue` |
| `--format md\|csv` | так | формат звіту |
| `--out <file>` | ні | писати звіт у файл, а не в stdout |
| `--help`, `-h` | — | показати рядок використання і вийти з кодом `0` |

**Без `--out`:** звіт іде в stdout, звіт помилок — у stderr. Зручно для `| head`, `> report.csv`, порівняння в CI.

**З `--out`:** звіт пишеться у вказаний файл, а проблеми — у `<out>.errors.csv` поруч. Цей файл перезаписується щоразу, тож після чистого запуску в ньому лишається тільки заголовок — старі помилки не «залипають». У stderr тоді йде лише короткий підсумок:

```
$ node dist/cli.js --spend spend.csv --revenue revenue.csv --format csv --out report.csv
Пропущено рядків: 7, деталі: report.csv.errors.csv
```

## Вхідні файли

Два CSV, по одному на витрати і доходи. Мінімальний приклад:

`spend.csv`

```
campaign,spend
winter-sale,1200.50
black-friday,3400.00
```

`revenue.csv`

```
campaign,revenue
winter-sale,2400.00
black-friday,2890.75
```

Що приймається:

- **Колонки за назвою, не за позицією.** Потрібні `campaign` і `spend` (або `revenue`). Регістр і пробіли в заголовку не важливі (`  Campaign `, `SPEND`), зайві колонки ігноруються. Порядок колонок довільний.
- **Розділювач `,` або `;`** — визначається автоматично за рядком заголовка. Можна оголосити явно рядком `sep=;` або `sep=,` перед таблицею (так робить Excel) — цей рядок не зсуває номери рядків у звіті помилок.
- **Дробова частина через `.` або `,`.** Кома як дріб працює лише коли поле взяте в лапки (`"1 234,50"` ні, `"1234,50"` так) або коли розділювач — `;`. Інакше `1,5` — це два поля, а не число.
- **UTF-8**, з BOM або без. CRLF і LF обидва підходять. Файл в іншому кодуванні відхиляється з підказкою.
- **Порожній розділювач у кінці рядка** (`Promo,100,`) — нормально, навіть якщо в заголовку його немає.
- **Дублікати кампанії** в кількох рядках — суми додаються.
- **Мінусові суми** — приймаються (повернення, корекції).

## Вивід

Той самий звіт у двох форматах. CSV:

```
campaign,spend,revenue,ROI
black-friday,3400.00,2890.75,-14.98%
brand-awareness,750.25,1500.00,99.93%
winter-sale,1200.50,2400.00,99.92%
Total,5350.75,6790.75,26.91%
```

Markdown — те саме, з вирівнюванням чисел праворуч (приклад на початку README).

Деталі, які корисно знати:

- Кампанії відсортовані за назвою, `Total` завжди останній.
- Гроші — завжди два знаки після коми, крапка як дріб, без розділювача тисяч.
- ROI — два знаки і `%`; `-` коли ROI не визначений.
- У CSV лапкування за RFC 4180: поле беруть у лапки лише коли в ньому є кома, лапка або перевід рядка. У markdown у назвах екранується `|`.
- Вивід завжди в UTF-8 без BOM, з LF і фінальним переводом рядка.

## Правила підрахунку

- `ROI = (дохід - витрати) / витрати × 100%`.
- Якщо **сумарні витрати кампанії ≤ 0**, ROI не визначений і в клітинці стоїть `-`. Те саме правило для рядка `Total`.
- ROI рядка `Total` рахується від загальних сум, а не як середнє по кампаніях.
- Кампанія, яка є лише в одному файлі, все одно в звіті; відсутнє значення = 0.
- Гроші рахуються в мінорних одиницях валюти (сума × 100, ціле число) — без float, тому копійки не «пливуть».
- Округлення ROI — **half away from zero**, як `ROUND` в Excel: `0.075%` → `0.08%`, `-37.375%` → `-37.38%`. Рахується цілими числами з мінорних одиниць, не з дробового ROI.
- У назвах кампаній обрізаються пробіли по краях.
- Назви зливаються без урахування регістру, типу апострофа (`'` `ʼ` `’` `‘` `` ` ``), нерозривного пробілу і невидимих символів. У звіт іде перше написання, очищене від невидимих символів.

## Звіт помилок

Той самий набір проблем рендериться двояко. У **stderr** — рядками, з підсумком у кінці:

```
spend.csv:3: порожня сума
spend.csv:4: сума не число: "abc"
spend.csv:5: порожня назва кампанії
spend.csv:6: порожня назва кампанії
spend.csv:7: більше 2 знаків після коми: "10.555"
spend.csv:9: замало полів: 1, у заголовку 2
revenue.csv:3: сума не число: "1 234.00"
Пропущено рядків: 7
```

У **`<out>.errors.csv`** — таблицею:

```
file,line,type,message
spend.csv,3,error,порожня сума
spend.csv,4,error,"сума не число: ""abc"""
spend.csv,5,error,порожня назва кампанії
spend.csv,6,error,порожня назва кампанії
spend.csv,7,error,"більше 2 знаків після коми: ""10.555"""
spend.csv,9,error,"замало полів: 1, у заголовку 2"
revenue.csv,3,error,"сума не число: ""1 234.00"""
```

Обидва приклади — справжній вивід на `fixtures/broken-rows/`.

`Пропущено рядків` рахує все, що привʼязане до номера рядка: і биті рядки, і пропущені рядки підсумку. Проблеми рівня файлу номера рядка не мають і в лічильник не йдуть.

### Рядкові проблеми

Рядок пропускається, звіт будується з решти.

| Повідомлення | Коли |
| --- | --- |
| `порожня сума` | у колонці суми порожньо |
| `сума не число: "…"` | не число, зокрема розділювач тисяч (`1 234.00`) або два різних розділювачі |
| `більше 2 знаків після коми: "…"` | `10.555` — тихого округлення не робимо |
| `сума довша за 15 цифр: "…"` | у колонку суми потрапив ID кампанії |
| `сума завелика для точного підрахунку: "…"` | формально 15 цифр, але в мінорних одиницях вже за межею точних цілих |
| `порожня назва кампанії` | назва порожня або лише з пробілів |
| `замало полів: N, у заголовку M` | у рядку менше полів, ніж у заголовку |
| `забагато полів: N, у заголовку M (дріб через кому треба брати в лапки)` | зайве **непорожнє** поле, майже завжди дріб через кому |
| `пропущено рядок підсумку: "…"` | попередження: рядок `Total`, `Разом`, `Усього`, `Підсумок`, `итого`, `Total: …`, `Разом: …` з самого вивантаження |

### Проблеми рівня файлу

| Повідомлення | Тип |
| --- | --- |
| `порожній файл`, `немає рядків з даними` | попередження, звіт будується з нулями |
| `злито: Black<U+00A0>Friday, Black Friday` | попередження: кілька написань однієї назви; невидимі символи показані кодами |

### Фатальні помилки

Звіту немає, код виходу `1`, у режимі `--out` жоден файл не створюється.

| Повідомлення | Коли |
| --- | --- |
| `немає колонки "campaign"` / `немає колонки "spend"` | не той файл або битий заголовок |
| `колонка "spend" у заголовку двічі` | незрозуміло, яку брати |
| `файл не в UTF-8, збережіть як CSV UTF-8` | Windows-1251, UTF-16 тощо |
| `помилка лапок (…), виявлено в рядку N; файл не прочитано` | будь-яка проблема з лапками |
| `назва з переносом рядка, ймовірно зайва лапка` | лапка склеїла кілька рядків в одну назву |
| `не можу прочитати файл: …`, `не можу записати файл: …` | немає файлу, немає прав |
| `невідомий аргумент: …`, `аргумент … без значення`, `немає обовʼязкового аргументу --spend`, `--format має бути csv або md, а не "…"` | аргументи |

## Коди виходу

| Код | Коли |
| --- | --- |
| `0` | звіт побудовано — навіть якщо частину рядків пропущено |
| `1` | фатальна помилка: аргументи, файл, кодування, заголовок, лапки |

Код `0` при пропущених рядках — свідоме рішення: один битий рядок не повинен валити весь звіт. Якщо обгортка має реагувати на пропущені рядки, перевіряйте stderr або `<out>.errors.csv`.

## Відомі обмеження

Усе нижче — відома й свідома поведінка, а не плани. Якщо щось із цього заважає, це окрема задача.

**Дані, які зникають або зливаються**

- Кампанія, яка **справді** називається `Total`, `Разом`, `всього`, `усього`, `итого`, `підсумок`, або починається з `Total:` чи `Разом:`, пропускається як рядок підсумку з вивантаження. У звіті помилок про це є попередження, рядок рахується в `Пропущено рядків`, але гроші в звіт не потрапляють.
- Рядок, у якому бракує лише останнього необовʼязкового поля (заголовок `campaign,spend,note`, рядок `Promo,100`), відкидається цілком як «замало полів». Помилка видна, але сума зі звіту зникає.
- Суми довші за 15 цифр відкидаються: далі `Number()` почав би тихо губити молодші цифри.
- Відʼємні та нульові витрати дають ROI `-`. Повернення коштів зменшують рядок `Total` без окремого попередження.

**Шум у звіті помилок**

- Порожні рядки з Excel (`,,` або `;;`) дають помилку «порожня назва кампанії» на кожен такий рядок і роздувають `Пропущено рядків`. Порожнє поле **в кінці** рядка (`Promo,100,`) помилкою не вважається.
- Для запису в лапках, що займає кілька рядків, у звіті вказано **останній** рядок запису, а не перший.
- Номер рядка у фатальній помилці лапок — це рядок, на якому спинився парсер, а не той, де лапка відкрилась: цього парсер не знає. Тому в тексті написано «виявлено в рядку N».

**Читання файлу**

- Розділювач визначається за першим рядком. Якщо коми і крапки з комою там однаково часто (`campaign;spend, UAH`), обирається кома і файл не читається. Обхід: додати першим рядком `sep=;`. Але це лікує тільки розділювач — колонка в цьому прикладі називається `spend, UAH`, а шукається рівно `spend`, тому заголовок усе одно доведеться виправити.
- Будь-яка інша преамбула над таблицею (порожній рядок, заголовок звіту, `sep=` з іншим символом) зʼїдає рядок заголовка — буде фатальна помилка «немає колонки campaign».
- **Будь-яка** помилка лапок фатальна для всього файлу. Лапка зʼїдає рядки до наступної лапки, тому частковий звіт тихо губив би гроші. Це стосується і незакритої лапки, і лапки всередині незалапкованого поля (`Акція "VIP",100`), і сміття після закритої лапки (`"Акція"x,100`).
- Назва кампанії з переносом рядка всередині — теж фатальна. Формально це валідний CSV, але на практиці так виглядає зайва лапка, що склеїла кілька рядків в один.

**Вивід**

- CSV завжди з розділювачем-комою і крапкою в числах. Excel з українською локаллю може відкрити такий файл одним стовпцем, а суми на зразок `12.05` прочитати як дати. Обхід: імпорт через «Дані → Отримати дані → З текстового файлу».
- Назви, що починаються з `=`, `+`, `@` або `-`, у CSV префіксуються апострофом, щоб Excel не виконав їх як формулу. У клітинці буде видно цей апостроф.
- Перенос рядка в назві кампанії ламає markdown-таблицю: екранується тільки `|`. (У вхідних даних така назва фатальна, тож дійти до виводу вона може лише програмно.)

**Режим `--out`**

- Звіт пишеться раніше за `<out>.errors.csv`. Якщо запис файлу помилок не вдасться, звіт уже на диску — лишиться напівстан.
- Повторений прапорець мовчки бере останнє значення: `--spend a --spend b` прочитає `b`.
- ROI рахується цілими числами з мінорних одиниць. Якщо різниця доходу і витрат перевищує приблизно 9 млрд одиниць валюти, чисельник (× 10000) виходить за межі точних цілих.

## Розробка

```
npm test            # vitest; перед запуском сам збирає dist/, бо e2e гонить справжній CLI
npx tsc --noEmit    # перевірка типів, включно з тестами
npm run build       # tsc -> dist/
```

Структура:

```
src/types.ts      спільні типи
src/parse.ts      читає CSV: нормальні рядки + список проблем
src/aggregate.ts  зведення по кампаніях, ROI, Total
src/format.ts     вивід у csv/md і два рендери звіту помилок
src/cli.ts        аргументи, файли, виклики
fixtures/         вигадані CSV під крайові випадки + еталонний вивід
tests/            юніт-тести на кожен модуль + e2e на кожну папку fixtures
```

`parse`, `aggregate` і `format` — без побічних ефектів: читання і запис файлів живе лише в `cli.ts`.

Кожна папка в `fixtures/` — це пара вхідних CSV і еталонний вивід (`expected.csv`, `expected.md`, `expected-errors.txt`, `expected-errors.csv`). e2e-тести порівнюють з ними **побайтово**, тому фікстури — не просто дані, а специфікація формату. Покриті випадки: кампанія лише в одному файлі, коми й лапки в назвах, розділювач `;` з дробом через кому, BOM з CRLF, биті рядки, порожній файл, дублікати з різним регістром, нульові та відʼємні витрати, відсутня колонка.
